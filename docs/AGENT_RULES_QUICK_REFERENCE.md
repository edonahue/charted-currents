# Agent rules — quick reference

Use `GEMINI.md` as the project constitution and `docs/AGENT_CONTEXT_INDEX.md` to route into deeper context.

Before substantial work:

- inspect `git status` and preserve unrelated work;
- identify the bounded objective and acceptance criteria;
- read `docs/MAINTAINER_EXPECTATIONS.md`;
- read `docs/PUBLIC_PRIVATE_BOUNDARY.md` before committing data/config/screenshots/logs/benchmarks/environment/source artifacts;
- prefer existing decisions and canonical sources of truth;
- choose simple reversible local details without reopening product strategy;
- do not invent history or verification evidence;
- run the smallest relevant checks while iterating and the appropriate completion gate before handoff;
- keep docs synchronized with what actually exists;
- report **changed / verified / unresolved / next** and stop at the agreed boundary.
