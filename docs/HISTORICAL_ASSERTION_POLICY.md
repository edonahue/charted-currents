# Historical assertion policy

This document defines how Charted Currents classifies historical claims for review and publication.

The classification is an **epistemic-risk and review-burden taxonomy**. It is not a numeric truth score and must not replace the project's evidence states in `docs/PROVENANCE_AND_UNCERTAINTY.md`.

When a claim fits more than one class, use the highest-risk class that materially affects its meaning.

## Assertion classes

### Class A — direct / transcribed

A bounded source-fidelity claim that reproduces an observed source value without historical inference.

Examples:

- a dataset row records `278` in a tonnage field;
- a catalogue record gives a particular signatura;
- a map visibly labels `Port Royall`;
- a manuscript page, when actually inspected, contains a particular date or name.

Requirements:

- exact SourceRecord;
- exact inspection state;
- raw value preserved;
- source layer identified;
- no stronger wording than the source supports.

Default scalable review: deterministic/source comparison where possible plus sampling.

### Class B — deterministic transformation

A reproducible transformation whose output follows mechanically from source data and an explicit rule.

Examples:

- `Cádiz` → `cadiz` for a search key;
- converting a documented unit using a declared conversion rule;
- parsing a year from a source field without adding precision;
- extracting a commander from a compound field using a documented deterministic parser.

Requirements:

- input assertion/source record retained;
- transformation rule documented and tested;
- raw input never overwritten;
- transformation cannot silently add historical meaning.

Default scalable review: test the rule thoroughly; sample outputs rather than hand-reviewing every transformed value.

### Class C — relational / derived

A claim produced from explicit joins, aggregation, or other deterministic relationships among source records.

Examples:

- a vessel record with `FLOTAS CONOCIDAS = 141` is joined to FLOTAS row `141`;
- a count of records belonging to a documented fleet;
- grouping archival routes by identical resolved endpoint pair for display.

Requirements:

- every input source record/assertion is traceable;
- join/aggregation rule is explicit;
- one-to-many, missing, duplicate, and conflicting keys are handled visibly;
- project-derived counts are labeled project-derived rather than source-native.

Default scalable review: validate joins mechanically, inspect edge cases and sample successful joins.

### Class D — identity / resolution

A judgment that multiple occurrences refer to the same historical person, vessel, place, organization, event, or other canonical entity, or that one occurrence should resolve to a canonical entity.

Examples:

- four `Bartolomé Antonio Garrote` master occurrences probably refer to one person;
- two similarly named vessels should remain separate because masters/destinations conflict.

Requirements:

- occurrence-level evidence preserved;
- explicit positive discriminators;
- explicit contradictory/negative evidence;
- source dependencies identified;
- missing discriminators identified when material;
- resolution state remains reversible;
- name equality alone is insufficient;
- a resolution dossier exists for non-trivial cases.

Default scalable review: adversarial review of all consequential or low-confidence resolutions; automation may prioritize cases but may not silently merge them.

See `docs/ENTITY_RESOLUTION_POLICY.md`.

### Class E — historical interpretation

A claim that explains significance, institution, motive, social meaning, historical pattern, or context beyond the literal source assertion or deterministic relation.

Examples:

- describing a port as strategically important to a particular commercial system;
- arguing that repeated records demonstrate career continuity or institutional practice;
- explaining what a convoy reveals about Spanish imperial commerce.

Requirements:

- distinguish description from interpretation;
- cite appropriate secondary scholarship or other explicit interpretive support;
- identify where the statement is the project's synthesis;
- report important competing interpretations where material;
- avoid presenting plausible model-generated prose as self-evident history.

Default scalable review: 100% review of new public interpretive claims until the project has a mature secondary-scholarship workflow.

See `docs/SECONDARY_SCHOLARSHIP_POLICY.md`.

### Class F — reconstructed

A claim generated by an explicit historical/computational reconstruction rather than directly observed historical evidence.

Examples:

- a probable sailing route reconstructed from period navigation assumptions and winds;
- reconstructed weather/current conditions;
- inferred movement between dated observations.

Requirements:

- model and inputs documented;
- assumptions and uncertainty visible;
- source observations remain distinguishable from reconstructed outputs;
- reconstructed geometry/values use distinct public semantics and styling;
- validation method and limitations documented.

Default scalable review: model/method review plus targeted historical/domain review. Reconstruction never becomes `documented` because reviewers agree with it.

### Class G — causal / synthetic historical argument

A claim that one event, institution, policy, actor, environmental condition, or other factor caused or materially drove another historical outcome.

Examples:

- a war caused a change in traffic;
- an earthquake redirected a commercial network;
- a policy change explains a capture pattern.

Requirements:

- explicit supporting secondary scholarship and/or a defensible analytical method;
- alternative explanations considered;
- correlation is not described as causation;
- source coverage and denominator limitations disclosed;
- high review burden.

Default scalable review: maintainer/adjudicator review and, for consequential public claims, prefer qualified external review before presenting the claim strongly.

## Claim class does not equal evidence state

These concepts answer different questions.

- `claim_class` asks **what reasoning operation produced this claim and how much review it needs**.
- `evidence_state` asks **how the project characterizes the historical support** (`documented`, `probable_match`, `reconstructed`, `contextual`).
- `review_state` asks **what review process this claim has undergone**.

Examples:

- a Class D identity may have `evidence_state: probable_match` and later `review_state: expert_reviewed`;
- a Class A transcription may have `evidence_state: documented` but still be `review_state: source_qa_pending` during ingestion;
- a Class F model output should remain `evidence_state: reconstructed` even after extensive review.

## Review strength cannot upgrade evidence strength

This is a permanent project invariant.

- Ten AI auditors agreeing with a Class D inference do not create ten historical sources.
- A qualified historian reviewing a probable identity does not make it a direct source assertion.
- A deterministic parser passing every test does not make the underlying source more authoritative.

Review establishes confidence in the **project's handling of evidence**. It does not change what the evidence is.

## Source fidelity and historical conclusion are separate questions

A claim may have very high source fidelity but weak historical implications.

For example:

1. `TODOSNAVIOS` unquestionably records a name in a master field — high source-fidelity Class A claim.
2. Several such rows probably refer to one physical person — separate Class D resolution.

Never collapse those into one confidence field.

## Contradictions and counter-evidence

For Class D–G claims, known contrary evidence must be attached to the review decision or dossier when material.

Do not hide counter-evidence in free-form notes that public or future review tooling cannot discover.

A contradiction may produce:

- a downgraded claim;
- an unresolved result;
- multiple competing assertions;
- a contested state;
- no publication at all.

All are legitimate outcomes.

## Public prose classification

When agents write historical copy, classify the underlying statements at least conceptually as:

- `evidence_description` — states what sources record;
- `project_methodology` — explains what Charted Currents did;
- `historical_interpretation` — Class E;
- `causal_interpretation` — Class G.

The last two require a stronger support path than ordinary source-card copy.

## Minimum future assertion/review metadata

The interstitial scholarly-review implementation may refine exact schemas, but new machinery should be able to represent, directly or by references:

- assertion/claim ID;
- claim class;
- source record IDs;
- raw/source values;
- evidence layer and inspection state;
- transformation/derivation steps where applicable;
- supporting assertion IDs;
- contrary/conflicting assertion IDs;
- evidence state;
- review state;
- reviewer type/agent only where public-safe and useful;
- review notes/rationale for high-risk claims;
- corpus/version information.

Do not add fields merely to satisfy this list if existing project structures already carry the same meaning. Prefer references and one source of truth.
